# Outside services: what is real, what is only tested against stand-ins

Status after review of the code (timeouts, retries, error handling, logging, signature checks, tests). **"Real provider" means the code was run against the provider itself. None were: no live credentials were used when this was written.** Each row says what the tests do instead, and exactly what is left to check with your own credentials.

| Service | Used for | Settings | Timeout | Retry | Errors / logging | Verified how | Still to check with real credentials |
|---|---|---|---|---|---|---|---|
| **Clerk** | Sign-in, session tokens, profile and verified email | `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` or `CLERK_JWT_KEY`, `CLERK_ISSUER` | Token check is local (public key) or cached JWKS; profile/delete calls 10 s | None; a slow Clerk answers 503 and the page retries | 401 reasons counted in `auth_failures_total`; Clerk failures in `integration_failures_total{integration="clerk"}` | Unit tests with locally signed tokens (signature, expiry, issuer, authorised party, `sts`); web redirects checked in a real browser | Everything in Clerk's own screens (see [TESTING.md](TESTING.md) §3); the dashboard settings list there |
| **Stripe** | Checkout, customer portal, seat quantity, webhooks | `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_PLUS/PRO/BUSINESS` | 20 s | None on the request; the webhook is retried by Stripe, and handling is idempotent (stored event ids) | Failures counted per integration; messages shown are safe; signature check is HMAC-SHA256, constant time, 5-minute tolerance | Contract tests against a local stub of Stripe's API and signed webhook fixtures | One test-mode checkout, a subscription change, a cancellation, and a webhook delivery from Stripe's dashboard ("Send test webhook") |
| **Anthropic** | AVEN Intelligence, agents, workflow AI steps | `ANTHROPIC_API_KEY`, `AI_MODEL`, `AI_BASE_URL` | 5 minutes per answer, and the caller's own abort | None: the person retries; credits are only charged for output actually produced | Provider errors become plain messages (key rejected, rate limited, unavailable); counted in `ai_request_failures_total` and `integration_failures_total` | Contract tests against a local streaming stand-in (text, tool calls, errors, credits) | One real conversation with a tool call and a confirmed action; usage numbers against Anthropic's dashboard |
| **Resend** | Invitation and summary emails | `EMAIL_API_KEY`, `EMAIL_FROM`, `EMAIL_BASE_URL` | 15 s | Summaries: reset and retried with backoff, never repeated in a loop; invitations: the link is still shown if sending fails | Failures counted; no recipient addresses in logs (scrubbed) | Contract tests against a local stub | Domain verification and one real invitation email to an address you own |
| **Google / Microsoft calendars** | Two-way event sync | `GOOGLE_CLIENT_ID/SECRET`, `MICROSOFT_CLIENT_ID/SECRET`, `TOKEN_ENCRYPTION_KEY`, `API_PUBLIC_URL` | 20 s | Failed syncs are retried on the next pass; "auth" failures ask the person to reconnect | Failures counted; tokens stored encrypted (AES-256-GCM); the access token is only ever sent to the provider's own address, including for paged results | Integration tests against a local calendar stub (import, duplicates, conflicts, deletions, reconnect); a unit test for the next-page address | The OAuth consent screens (redirect URIs, scopes) and one real sync each way. Use a test calendar |
| **S3-compatible storage** | File contents | `STORAGE_DRIVER=s3`, `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_ENDPOINT` | 2 min writes, 10 min reads | None; the upload fails and nothing is left behind | Failures counted per method; files are never public, and downloads go through the API's permission checks | SigV4 signing against Amazon's published test vector; driver tests against a local server and a stub | A real bucket: upload, download, delete, and that the bucket is private. Bucket versioning and a region in Australia if data residency matters |
| **Brave Search** | Web research for the assistant | `WEB_SEARCH_API_KEY` | 10 s | None | Failures counted | Contract tests against a stub | One real search; check the plan's rate limit |
| **Embeddings** (any OpenAI-compatible endpoint) | Search by meaning | `EMBEDDINGS_API_KEY`, `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_MODEL` | 30 s | The next search retries unindexed items | Failures counted | Integration tests against a stand-in; results respect workspace and project visibility | One real indexing run; check cost for a large workspace |
| **Browser push** | Notifications | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | 10 s, no redirects, public addresses only | Expired subscriptions are removed; others retried next pass | Failures counted | Encryption and VAPID signing tests; delivery against a local stand-in | A real device on a real push service (Chrome, Firefox, Safari); iPhone needs the installed web app |

Never run these checks with production customer data, take real payments, send email to people who did not ask for it, or change a production calendar.
