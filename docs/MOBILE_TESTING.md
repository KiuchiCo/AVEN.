## Full verification run (this machine)
API unit 290/290; API integration 201/201 on a freshly migrated database; web unit 190/190; web components 37/37; mobile 4/4; web `tsc` clean and `eslint` clean; web production build succeeded; `npm audit --omit=dev` 0 vulnerabilities; secret scan (history and working tree) no findings after allow-listing the PEM header text in `api-environment.ts`. iPhone 17e landscape: the offline page rotates and stays intact (offline page only). Still unverified: signed-in UI on any device, iPhone 17 Pro Max, iPad Pro 13, iPad landscape and split view, VoiceOver, performance, and every real-device feature.
- **Development build on iPhone 17e (portrait) against the local web server:** the real Clerk sign-in page loads in the native shell. First look showed the AVEN. wordmark overlapping the clock (no top safe-area padding on `.auth-page`); fixed in `globals.css` and re-checked in the simulator, and the wordmark now sits clear of the status bar. The small "◂ Safari" at the top is iOS's return-to-previous-app indicator from the simulator launch, and the round "N" is Next.js's dev-mode badge; neither is in the app.
- **Signed in on iPhone 17e (a real Clerk account supplied by the user, development build, local API and database):** Home, My Tasks and Settings load with real data and the bottom tab bar appears with the current tab highlighted. Three defects were found by looking and fixed: (1) a crash in `NativeEvents` cleanup (`listener.then is not a function`: the bridge returns a handle, not a promise); (2) the top bar overlapped the status bar (its minimum height did not include the safe-area inset); (3) the page could scroll sideways and clipped the left edge (`overflow-x: clip` on phones). Re-checked on this one device only. The first "could not load your workspace" screen was because the API was not running and the dev database was missing two new migrations; both are environment setup, not app bugs. In dev builds the Next.js "N" badge covers the tab bar's "More" label.
- **iPad Air 11-inch, signed in, landscape (development build):** the persistent sidebar, top bar with search, and no tab bar render as designed; Home, Calendar and Knowledge load with real data. Found and fixed: the sidebar wordmark overlapped the status bar (safe-area padding), and two- and three-field form rows (Calendar "Starts/Ends", Knowledge "Source URL/Tags" and the project/document/task selects) overflowed or clipped their values (grid columns now shrink and wrap). After the change the Knowledge form was re-checked in a rotated, partly cropped simulator screenshot and looked right; the Calendar event form was not re-checked, and other forms with the same grid pattern were not audited. `aven://knowledge` opened the Knowledge screen after iOS's "Open in AVEN." prompt (deep link verified on this device). Portrait, Split View and iPad Pro 13 are untested.
- **Optimisation pass:** the top bar overlapped the status bar on iPhone 17e (a later `redesign.css` rule fixed its height and overrode the earlier safe-area rule); a final rule now adds the safe-area inset to the bar's padding and height. Re-checked on iPhone 17e (cold launch) and the iPad Air (landscape). Inbox opened through an `aven://inbox` deep link on the iPhone. The "/" menu's highlighted row now runs edge to edge (iPad). Not covered: iPhone 17 Pro Max and iPad Pro 13 were booted and the app installed, but they are signed out (Clerk emails a code per device), so no signed-in screens were audited there; portrait iPad, Split View, and screens other than Home, Inbox, My Tasks, Settings, Calendar, Knowledge and Documents were not audited.
